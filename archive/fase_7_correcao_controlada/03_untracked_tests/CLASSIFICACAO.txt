## Contexto adicional (fato não previsto no prompt original)
`git status --porcelain | grep "\.py$"` mostra que a maioria de `tests/*.py`
TAMBÉM está untracked (test_api_gateway.py, test_config.py, test_fallback.py,
test_fallback_activation.py, test_llm_manager.py, test_memory_opt.py,
test_web_search.py, test_ws_metrics.py, debug_test.py, quick_test.py — 10 de
14 arquivos). Só test_coordinator_triage.py, test_fallback_chain.py,
test_memory_integration.py e test_ollama_client.py estão de fato versionados.
Ou seja, "estar untracked" por si só NÃO distingue os dois arquivos da raiz do
restante da suíte — a maior parte da suíte hoje usada como baseline também
nunca foi commitada. O critério decisivo para classificação, portanto, não é
o status do git, e sim a compatibilidade com a API real (abaixo).

Arquivo: test_ollama_integration.py
---------------------------------------
Origem:        Untracked (`??`). `git log --all --full-history` → nenhum
                resultado. Nunca esteve em nenhum commit deste repositório.
Dependências:   `from src.core.memory_manager import MemoryManager` (existe,
                é alias de MemoriaPersistente) e
                `from src.core.llm_manager import LLMManager, GenerationConfig`
                — GenerationConfig NÃO existe (`class GenerationConfig`:
                NOT_FOUND em src/).
Compatibilidade: Falha na importação (ImportError), confirmado na Fase 5/6.
                Mesmo corrigindo o import, o script chama APIs que não
                correspondem à implementação atual:
                  - `LLMManager(model_name=..., backend=..., cache_enabled=...)`
                    — construtor real é `LLMManager(config: dict, memory_manager)`.
                  - `llm.generate(...)` tratado como síncrono — método real é
                    `async def generate(...)`.
                  - `llm.generate_stream(...)` — não existe (só métodos
                    privados `_generate_stream*`).
                  - `llm.get_stats()` (na classe LLMManager) — não existe.
                  - `MemoryManager(storage_path=Path(...))` — construtor real
                    usa `db_path`, `index_path`, `max_memories`, `ollama_client`.
                  - `memory.add_user_message(...)`, `memory.get_context(...)`
                    — não existem (API real é `salvar_memoria()` assíncrono).
Cobertura:      Também não é um teste pytest de fato — é uma classe
                `OllamaIntegrationTest` sem prefixo `Test`, sem métodos
                `test_*` no sentido pytest, executada via
                `if __name__ == "__main__": tester.run_all()`. Mesmo com
                import corrigido, pytest coletaria ZERO testes deste arquivo
                (o nome `test_*.py` faz o pytest tentar importar o módulo,
                mas não há nada dentro que o pytest reconheça como caso de
                teste). É por isso que o efeito observado é sempre "erro de
                coleção", nunca "teste falhando" — não há teste pytest aqui.
Natureza:       EXPERIMENTAL / script de smoke-test manual, escrito contra
                uma API especulativa que nunca existiu no histórico
                versionado, e nunca funcional mesmo como script standalone
                contra o código atual.

Classificação: DELETE
Justificativa: (1) Depende de uma classe que nunca existiu no histórico git.
               (2) Todos os outros símbolos que chama também divergem da API
               real (nomes de parâmetro, sync/async, métodos inexistentes) —
               não é um caso isolado de rename, é dessincronia completa.
               (3) Não é estruturalmente um teste pytest — não agrega
               cobertura à suíte mesmo se reparado. Se for necessário um
               smoke-test manual de integração com Ollama no futuro, deve
               ser reescrito do zero contra a API real e, preferencialmente,
               renomeado para não colidir com o padrão `test_*.py` do pytest
               (ex.: `smoke_ollama.py`), ou reescrito como teste pytest de
               verdade.
